## 2026-11-27

### 재실행 시 세션·배치 자동 복원
- 열린 창·순서·위치·연결 세션을 `(자동) 마지막 상태` 작업 세트로 자동 저장(창 집합 변화·정렬·종료 시)
- 앱 재시작 시 자동 적용: 열린 창은 저장 위치로, 닫힌 세션은 순차 재실행(Claude `claude -c`, GPT `codex resume <id>`) 후 배치. 복원 뒤 목록 순서를 화면 위치로 재설정
- 창↔세션 연결: 창 제목 본문 = 세션 이름 정확 일치 우선, 나머지는 같은 종류 최근 세션 근사
- Windows 종료(SessionEnding) 시 동기 저장 후 저장 동결 → 터미널이 먼저 닫혀도 빈 상태로 덮어쓰지 않음
- 세션 스캔(`GetRecent`) 약 0.7초(실측 722ms) → 평상시 자동 저장은 백그라운드 작업, 파일 쓰기만 UI 스레드. 종료·Windows 종료 시에만 동기 저장
- 작업 세트가 GPT 슬롯도 재실행하도록 확장(`WorkSetWindow.SessionKind`)
- 옵션 `재실행 시 세션·배치 복원`(기본 켜짐, `RestoreOnStart`)
- 모니터 선택·정렬 방향은 기존대로 `config.env`에 저장·복원
- 핵심 파일: `src/TileCLI/UI/MainForm.cs` `CaptureWorkSet`·`BuildWorkSet`·`AutoSaveState`·`CommitAutoSave`·`RestoreLastState`·`OnSessionEnding` / `src/TileCLI/Models/WorkSet.cs`
- 검증(테스트 빌드, 실제 앱): 첫 실행에 자동 세트 저장(창 3개, 제목으로 각자 세션 폴더 연결) / 닫힌 Claude·GPT 슬롯 2개 주입 후 재시작 → 순차 재실행, 저장 위치 정확히 배치(2560,0 855×696 / 2560,696 855×696) / 복원 후 자동 세트에 포함, 창 닫으면 제거됨 / 옵션 창 스크린샷 겹침 없음
- 한계: Windows 종료 경로(SessionEnding)는 실제 종료로 시험하지 않음. 세션 연결 근사는 제목 불일치 창에서 다른 세션에 연결될 수 있음

## 2026-11-17

### 새로 열린 일반 터미널 자동 최소화 + 제외
- 앱이 떠 있는 동안 새로 열린 일반(AI 아닌) 터미널은 최소화하고 `제외` 그룹에 넣음
- 그 창이 나중에 AI 창이 되면(claude/codex 실행 → 제목 마커) 제외를 풀고 복원, 감시 모드가 재배치
- 앱 시작 때 이미 열려 있던 창, TileCLI가 여는 세션 창(제목 `✳ `/`codex ` 고정)은 대상 아님
- Claude Code 작업 중 스피너 `◐◑◒◓`(U+25D0–U+25D3)를 AI 제목으로 인식. 이전엔 브라유 점자만 인식해 `◐ …` 창이 `Plain`으로 분류됐음 → 새 Claude 창이 오인 최소화될 수 있었음
- 핵심 파일: `src/TileCLI/UI/MainForm.cs` `MainForm.ParkNewPlainWindows` / `src/TileCLI/Services/WindowDiscovery.cs` `IsSpinnerPrefixed`
- 검증(실제 앱, 모니터 2): 새 일반 콘솔 → 최소화 / 제목을 `✳ …`로 변경 → 복원·재배치(T0~B1392) / WT `✳ …` 세션 창 → 최소화 안 됨 / `◐ …` 새 창 → 최소화 안 됨(kind Ai)

### 자동 배치 기본 방향을 가로 분할(세로로 긴 창 좌우 나란히)로 유지
- `⚡ 자동 배치`가 창 4개 이상에서 그리드로 바꾸고, 그 값이 저장돼 감시 모드 재배치에도 계속 쓰이던 문제 수정
- `TilingEngine.AutoDirection`: 개수와 무관하게 넓은 영역 → 가로 분할, 높은 영역 → 세로 분할
- 저장된 방향이 없을 때 기본값 Grid → 가로 분할(`MainForm._currentDirection`)
- 저장된 `Direction=Grid`는 가로 분할로 읽음(그리드 버튼·단축키는 방향을 저장하지 않아 Grid는 예전 자동 배치만 저장 가능했음)
- 검증: `--selftest`에 `[auto-dir]` 추가(1·2·3·4·6·9개 × 넓은/높은 영역) PASS, `--uitest` OK. 실제 앱에서 `Direction=Grid` 설정으로 실행 → 전체 높이 열 배치, 종료 후 `Direction=Horizontal`로 저장됨
- 한계: WT 최소 폭(약 466px) 때문에 2560px 모니터에서 6개 이상이면 열이 겹침

### 제외 항목 최소화(우클릭 메뉴 + 자동 최소화 옵션)
- 제외 항목 우클릭에 `창 최소화` 추가(선택한 행이 모두 제외 항목일 때만 표시)
- 옵션 `제외 항목 자동 최소화` 추가(기본 켜짐, `config.env`의 `MinimizeExcluded`): 제외 그룹에 새로 들어가는 창(새 일반 창·우클릭/드래그 제외·`AI 아닌 창 제외` 옵션)을 최소화. 켤 때 지금 제외된 창도 최소화. 끄면 제외만 하고 그대로 둠
- 시작 로드 중인 창, 사용자가 직접 다시 띄운 창은 다시 내리지 않음. 새 일반 창 정리는 제외만 하고 최소화는 이 옵션이 맡음
- 핵심 파일: `src/TileCLI/UI/MainForm.cs` `MainForm.MinimizeExcluded`·`MinimizeWindows`·`BuildTerminalContextMenu` / `src/TileCLI/UI/OptionsForm.cs`
- 검증(실제 앱): 옵션 끔 → 새 일반 콘솔이 `제외 (1)`에 들어가고 최소화 안 됨 / 우클릭 메뉴 `정렬에 포함·창 최소화·강제 종료` 표시, `창 최소화` → 최소화(상태 표시 `창 최소화: 1/1개`) / 창 복원 후 옵션 체크 → 다시 최소화, `MinimizeExcluded=true` 저장 / 옵션 켬 → 새 일반 콘솔 즉시 최소화. 옵션 창 스크린샷으로 배치 겹침 없음 확인
